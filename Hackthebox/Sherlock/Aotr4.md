## 🧭 Introduction – From Zero to Flight Forensics

The journey began with a simple but mysterious archive: **`AOTR4.zip`**.

At that moment, I had **zero prior knowledge** of drone flight controllers, MAVLink, or how UAVs log telemetry data. What I did have was curiosity, patience, and a **Never Give Up** mindset.

This Sherlock challenge wasn’t about traditional DFIR logs or PCAPs — it was about **understanding how a drone thinks**.

The mission:

* A criminal gang used a drone during a winter blackout
* The drone crashed in the snow
* Our task was to reconstruct the **entire flight**, from takeoff to impact

By combining documentation, AI-assisted research, and hands-on log analysis, I transformed raw binary flight data into a complete forensic timeline.

## 🧰 Toolkit & Evidence Overview

After extracting `AOTR4.zip`, the following key artifacts were identified:

### 📄 `AOTR_Winter_Blackout.plan`

* JSON-based mission file
* Used by **QGroundControl**
* Contains *planned* drone behavior

## 🧩 Part 1 – Mission Plan Analysis (`.plan` file)

### 🧠 Understanding Drone Commands

When first opening the `.plan` file, I encountered numeric command codes:

| Command | Meaning             |
| ------- | ------------------- |
| 22      | Takeoff             |
| 16      | Waypoint            |
| 21      | Land                |
| 19      | Loiter              |
| 82      | **Spline Waypoint** |

Spline Waypoints are crucial — they allow **smooth, curved flight paths** instead of sharp turns.

---

### ❓ Question 1: Total Mission Items

**Answer:** ✅ **49**

**Breakdown:**

* 48 items inside the `items` array
* 1 Planned Home Position

```bash
grep "type" AOTR_Winter_Blackout.plan | wc -l
```

✔️ **Total = 48 + 1 = 49**

---

### ❓ Question 2: Spline Waypoints Count

**Answer:** ✅ **46**

Spline waypoints (`command: 82`) represent smooth flight motion.

```bash
grep '"command": 82' AOTR_Winter_Blackout.plan | wc -l
```

🧠 **Why spline waypoints matter:**

* Battery efficiency
* Stable video recording
* Reduced noise
* Expert-level mission planning

## 🧪 Part 2 – Flight Log Forensics (`log.bin`)

Here, planning ends and **reality begins**.

---

### ❓ Question 7: Total Flight Time

**Answer:** ✅ **00:10:38.919**

```bash
Takeoff TimeUS : 48893768
Crash TimeUS   : 687813098
```

```text
(687813098 - 48893768) / 1,000,000 = 638.919 seconds
```

---

### ❓ Question 8: Crash Timestamp

**Answer:** ✅ **687813098 (TimeUS)**

```bash
mavlogdump.py log.bin | grep "SIM Hit ground"
```

---

### ❓ Question 9: Crash Coordinates

**Answer:** ✅ **47.4903055, 19.0460476**

```bash
mavlogdump.py --type GPS log.bin | grep -A 2 -B 2 "687"
```

Extracted from GPS entries nearest crash timestamp.

---

### ❓ Question 10: Impact Speed

**Answer:** ✅ **12.93254 m/s**

```bash
mavlogdump.py log.bin | grep "Hit ground"
```

Directly logged by flight controller on impact.

---

### ❓ Question 11: Maximum Altitude

**Answer:** ✅ **377.07 meters**

```bash
mavlogdump.py --type GPS log.bin | awk -F "Alt :" '{print $2}' | cut -d',' -f1 | sort -g | tail -n 1
```
The drone climbed steadily until it reached its peak of 377.07 meters before descending/crashing.

---

### ❓ Question 12: Maximum Ground Speed

**Answer:** ✅ **10.24 m/s**

```bash
mavlogdump.py --type GPS log.bin | awk -F "Spd :" '{print $2}' | cut -d',' -f1 | sort -g | tail -n 1
```
Similar to altitude, I looked for the maximum value in the Spd (Speed) column of the GPS logs.
---

### ❓ Question 13: Takeoff Coordinates

**Answer:** ✅ **47.4819399, 19.0191600**

```bash
mavlogdump.py --type GPS log.bin | head -n 10
```

📍 Near **Budapest University of Technology** — likely the operator’s physical location.
